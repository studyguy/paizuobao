# 排座宝 · P1 原型

中式宴席智能排座工具的可运行原型（P0 + P1 全功能）。对应《PerfectTablePlan 中国市场适配调研报告》的产品方案。

## 运行

```bash
pip install ortools        # 可选：启用 CP-SAT 云端求解（已验证安装）
python serve.py 8767       # 启动 P1 服务（静态 + API + 求解引擎）
# 打开 http://127.0.0.1:8767/
```

无 ortools 时自动降级为前端模拟退火引擎；直接双击 index.html 也可用（无分享/云端功能）。

## 交互形态（P1.5）

- **左侧双 Tab**：「👥 宾客」Tab = 搜索 + 导入/添加按钮 + 新郎方/新娘方/未标注筛选 chips + 按桌分组宾客列表；「🪑 布局」Tab = **可拖入画布的元素清单**（一行一元素：圆桌/舞台/墙面/卫生间/签到台/餐台/休息区——拖到画布松手即放置，干涉处放不下；单击行进入点击放置模式）
- **画布就地弹窗（可拖动）**：点击桌身或 ⚙ → 桌位弹窗（桌名/容量/主桌/删除，**改名即时生效**）；点击舞台 → 舞台弹窗（形状/宽/高/整体%缩放/删除）；点击卫生间等元素 → 元素弹窗（宽/高/整体%/删除）；弹窗初始居中偏上、**标题栏可整体拖动**；取消/关闭按钮不保存，点画布外/Esc 关闭
- **右侧抽屉**：配置类功能（AI建约束/宾客编辑/敬酒动线/分享RSVP/活动管理/付费墙）从右侧滑出边栏承载；礼俗检查按钮内置于右栏「礼俗报告」Tab 顶部
- **文案规范**：全站「男方/女方」→「新郎方/新娘方」（chips badge、宾客编辑、关系链下拉、礼俗报告、解析同义词）
- **画布缩放**：滚轮（含触控板捏合）以光标为中心缩放 40%~250%，右下角 −/＋/⤢ 控件；**⤢/初始/求解后/换示例后自动适应内容**（fitView 缩放居中，全部内容含门口一屏可见）；空白处拖拽平移，平移范围按内容边界放宽（内容投影最多移出 80%，永远留一角可见）
- **场地对象**：入口与舞台均为画布上可直接拖拽的对象——入口投影吸附到最近边缘（state.meta.door={side,t}），**各桌「上座」（0号位）几何朝向自动旋转为面向入口**（语义索引不变，礼俗/导出/大屏全部兼容）；舞台支持矩形/T形/圆形（state.meta.stage，T形为单路径12顶点一体轮廓、两侧凹角对称、细长走道比例），拖到哪算哪；脚本/CSS 带版本参数（?v=）防陈旧缓存
- **干涉检测（硬性）**：collision.js 统一几何（桌=圆 r113 含人；舞台/元素/墙=AABB；入口=圆 r58），任意对象间最小间隙 26px——拖动非法时沿单轴滑动、双轴非法则保持原位；新桌/元素落位自动 findFreeSpot 螺旋找空位；墙面（可调大小）拉伸同样受干涉约束
- **身份/宾客双维度约束**：约束带 scope（guest/role）；身份级（如「领导↔领导 不能同桌」）自动展开到该身份全部宾客对；**跨维度互斥检测**——新规则展开后与现有规则对同一对宾客给出相反的 must 结论即拒绝并报错（如身份级"领导不能同桌" vs 宾客级"王总↔李总必须同桌"），软冲突（prefer 级相反）确认后允许；常用约束模板一键添加（双方父母同桌/领导分桌/同学同桌等，按场景区分）；solver 与 CP-SAT payload 均使用展开后的宾客对
- **桌位编辑弹窗**：画布每桌右下角 ⚙ 小按钮（以及布局面板 ⚙）→ 弹窗设置桌名/容量/主桌/删除；容量改小后超出座位的宾客自动回「未安排」；紧凑档（tier≥1）齿轮仍可用
- **元素尺寸可调**：舞台/墙面/设施元素均支持宽、高独立调整与整体%等比缩放（弹窗数字输入 + 画布右下角红手柄自由拉伸），全程过干涉检测；桌子为圆桌语义（容量=人数），尺寸固定
- **动态逻辑空间（无硬边界）**：画布随内容向**四方**生长（引入逻辑空间原点 originX/Y，内容可拖到任意坐标含负值）；拖动/放置/拉伸均无方向性限制，唯一约束是干涉间隙；⤢/初始/求解后自动适应全部内容
- **紧凑渲染分档**：按每逻辑像素的 CSS 像素自动切档——完整档（≥0.68，全文字）、紧凑档（0.48~0.68，座位变高饱和色点、桌名加大加粗、★标上座、隐藏容量文字）、色点档（<0.48，进一步缩小座位），杜绝缩小后文字溢出

## 示例方案（真实场景还原）

- **婚宴（79 人 / 8 桌 / 82 座）**：T 台+主桌(12)居前、男左女右分列、晚辈近门；签到台/餐台/卫生间/新娘休息室齐备（画布不内置边框与墙，障碍物由用户自行拖入）；人情约束含二姨二舅拆迁纠纷（不能同桌）、副总与总监争权、堂哥嫂必须同偕、身份级「同学尽量同桌」；素食姑姑、清真同事、儿童餐、82 岁软烂饮食、2 位请假
- **年会（66 人 / 7 桌 / 70 座）**：大舞台、高管桌(9)居前、研发×2/市场/销售/职能/嘉宾家属桌分片；身份级「经理分散带桌」「家属不与员工混坐」、市场总监与销售经理抢预算（不能同桌）、跨部门夫妻想同坐（软约束权衡）；清真/素食/销冠/请假
- tests/test.js 对两个示例做**三重校验**：场地 16/15 个对象互不干涉、预置约束无硬互斥、必须同桌连通块 ≤ 最大桌容量

## 关键设计决策（踩坑记录）

1. **mustTogether 必须并查集成"块"调度**：单点移动跨不过硬约束势垒（动一人即违 10⁶ 惩罚被拒）。CP-SAT 侧对应 `x[a,t]==x[b,t]`。
2. **长辈梯度方向**：远桌平均辈分不得高于近桌；写反会把 VIP 全推离主桌。
3. **CP-SAT 方案多样性**：只约束"与上一解不同"会出现 A=C；必须对**所有**先前解加 ≥15% 差异约束。
4. **HTTP keep-alive 陷阱**：Handler 未读请求体就 return，残留 `{}` 会被解析成下一请求行（`{}POST`）导致后续请求全挂——do_POST/do_PUT 第一行必须消费 body。
5. **`os.path.join(ROOT, '/x.html')`** 在 Windows 得到 `\x.html`（绝对路径吞掉 ROOT）——静态文件服务必须先 lstrip('/')。
6. **多 `<script>` 微任务时序**：script1 的异步回调（微任务）在 script2 之前执行；跨脚本依赖的常量必须前置。
7. **NLP 称谓归一**：只用多字词做源（"新娘"的"娘"不可被单字规则误伤）；group 名不进别名池（"二姨一家"会让"二姨"歧义）。
8. **IAB 自动化**：rAF 冻结使 Playwright click 超时、cua.drag 缺 down/up——用 evaluate 派发合成 PointerEvent；截图用离屏 canvas + toDataURL（整页 screenshot 偶发可用，超时后勿立即重试）。
9. **IAB 冷启动 clientWidth=0**：canvas 初次 resize 得到 0 缩放且无人纠正——resize 跳过零宽 + render() 每帧自检 clientWidth 变化。
10. **模板化抽屉的绑定时机**：模板内 id 在 boot 时不存在 DOM——bindToolbar 里引用它们会 `null.addEventListener` 中断后续全部绑定（且无报错冒泡），模板内元素的监听必须在 openDrawer 之后挂。

## 已知限制（P2 候选）

- LLM 建约束为规则引擎 v1，LLM 代理钩子未实现真实转发（设 LLM_API_KEY 后返回 501 由前端兜底）
- 协作为 last-write-wins，无冲突合并与光标同步
- 多活动仅本地存储；分享服务数据在 data/store.json 明文
- 支付为模拟；正式版接微信支付
- 舞台避让已由干涉检测强制（拖动/放置均不可与舞台重叠）
